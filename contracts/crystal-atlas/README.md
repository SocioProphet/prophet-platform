# Crystal Atlas platform contracts

This directory holds the **platform-facing event schemas** for the Crystal Atlas lane.

## Scope

The contracts here represent:
- upstream extraction/enrichment outputs
- downstream contract/procurement intelligence outputs

These schemas are intended to be consumed by runtime services in `apps/` and validated by helpers in `tools/`.

## Event families

Everything listed below without a marker **ships as a schema in `events/`**. Entries
marked _(planned)_ are intent, not contract — they have no schema and nothing may be
built against them. `tools/tests/test_crystal_atlas_event_register.py` holds this list
to what is actually in `events/`, in both directions, so it cannot drift again.

### Reconstruction (three-space / LSA·LSI·LDA)

Contracts for **faithful reconstruction** of content a model has lost to compaction — topic
structure built over a raw corpus so evidence can be regenerated by topic, not by lossy recall.

- `reconstruction-manifest.v0` — a pinned, attested description of a reconstruction (document
  policy, seed/hash-pinned LSA/LSI/LDA spaces, declared coverage). Teeth: every space present must
  be pinned; `coverage.declared_gaps` is required.
- `topic-record.v0` — one topic carried as a **grounded** record (label + reasoning +
  representative evidence), not a bare term-list. `label`+`reasoning`+`mass` is a `claim.v0`; each
  `representative_evidence` item is an `evidence.v0` — so a reconstruction is a first-class
  producer into the graph. Teeth: `grounded=true` requires reasoning AND non-empty evidence.

Validated by `tools/validate_reconstruction_contracts.py` (`--selftest` proves the teeth bite both
ways), gated in `.github/workflows/reconstruction-contracts.yml`.
